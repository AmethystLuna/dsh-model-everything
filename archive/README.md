# 归档

放**不再现役**的文档：被发行物取代的计划、已结案的交接快照。归档不是删除——文件按归档时的原样留着，
读者仍能查到当时写了什么；但它**不再更新**，也不再是某个结论的现役出处。

## 规则

1. 归档只在「审计」时发生，一次一个批次，批次按年月命名，例如 `2026-10-audit/`。
2. 每个批次在本文件里有一节，逐条写：原路径、为什么归档、替代它的现役文档（没有就写「无」）。
3. 归档文件里的相对链接按原样冻结。它们可能指向已经不在原处的东西——这是冻结的代价，不是缺陷；
   要找「当时那个还活着的版本」，看 git 历史里同一路径的旧提交。
4. 现役文档不指向归档：读者顺着一个链接走进去，等于读了一份没有人维护的说法。
5. 进了归档就**不参与文档门禁**（`tests/memory`、`tests/documentation` 不看这里）。`markdownlint` 仍然覆盖它——
   格式的成本很低，而一份读不出段落的快照没有归档的价值。

## 归档了什么，没归档什么

这一轮审计的判据是三条，全部可核：

- **有门禁读它**：生成器、测试或索引读到的文件不动（`.github/memory/design/robustness-audit.md` 被三处原则引用，
  `design-review.md` 是参考文献的来源，`MEMORY.md` 与三个 `INDEX-*.md` 是入口）；
- **描述的是过去的状态，而现役文件已经取代它**：进归档（本批次的两份）；
- **描述的是现在的契约**：留着，哪怕里面的缺陷清单已经结案——把「已修」标上，契约仍然要按它读
  （`design/deployed-surface.md` 的两种拒绝形状就是这一类）。
